## 前言

**這本書是什麼**：Hermes Agent 不是聊天機器人，是一個會自我改進的 AI agent。它能讀檔案、跑指令、上網、記住你、自動化任務、甚至被拿去訓練新模型。這本書把官方全部文件重新編排成一套「由淺入深、每小時一個單元、邊讀邊做」的課程，目標是 100 小時後你**能獨立開發 Hermes 的外掛與技能**。

**誰該讀**：
- 想要一個「住在自己電腦裡、越來越懂你」的 AI 助理的用戶
- 想把 Hermes 變成 Telegram/Discord bot、自動化工作流的進階用戶
- 想為開源專案貢獻程式碼、開發 plugin / skill 的開發者

**誰不該讀**：只想聊天、不想動手操作的人——本書每節都有實作，不做等於沒讀。

**開課前準備（資源清單）**：
- **帳號**：建議先建好 Nous Portal 帳號（H3 會用到，免費）；Telegram（H31 選做，需要 bot token）；GitHub（H80 選做）——**另外建議註冊一個免費 GitHub 帳號**，本書配有讀者服務中心（見書末「讀者服務」），卡關時去那裡提問最快
- **硬體**：任一 Windows（WSL2）/ macOS / Linux 機器皆可；8GB RAM 以上較順；安裝約需 1-2GB 空間
- **成本**：H3 的 Portal 免費額度足夠走完本書主要章節；付費模型（H8）、外部服務（Docker/Ollama）為選做，用前先看價格
- **時間**：每天 2 小時 × 6-7 週；每節 1 小時為「閱讀 20 分＋動手 30 分＋驗收 10 分」的**理想估值**——遇到卡關請預留緩衝，別硬撐
- **心態**：本書最貴的不是軟體，是你的時間——驗收過不了就重做，不要帶著漏洞前進

**如何使用本書**：
1. 嚴格照順序。每一節建立在前一節之上，跳過會卡關。
2. 每節 1 小時 = 閱讀（約 20 分鐘）+ 動手做（約 30 分鐘）+ 驗收（約 10 分鐘）。
3. 每節末尾的「驗收」是繼續前進的門票——過不了就重做，不要硬闖。
4. 隨時查附錄 A 的指令小抄，不必背。

**版本聲明**：本書以 Hermes v0.21 為準撰寫。Hermes 迭代很快——書中出現的具體數量（技能數/N 個工具）、部分子指令可能隨版本增減。**一律以你安裝版本的 `hermes --version` 與 `hermes <指令> --help` 為準**；若書與實際不符，多數情況是版本差異而非你操作錯誤。

**約定**：🖥️ 終端操作 ｜ 📖 讀官方文件 ｜ 🧪 實驗比較 ｜ ✍️ 產出檔案

# 第 1 部 入門・會用（第 1-10 小時）

> **部導讀**：讀完本部，你將能獨立操作 Hermes 完成日常任務——部署、設定模型、使用工具，具備繼續深入的基礎。

## 第 1 章 認識與安裝（第 1-2 小時）

### 第 1 小時 ｜ Hermes 是什麼
- **動手做**：🖥️ `git --version`、`uname -r`（確認 WSL2）；📖 讀官方首頁與 Installation 開頭
- **內容重點**：agent 與 chatbot 的差異、自我改進學習迴圈、支援的平台
- **驗收**：能說出 Hermes 與一般 chatbot 的 3 個差異

### 第 2 小時 ｜ 安裝與健康檢查
- **動手做**：🖥️ `curl -fsSL https://hermes-agent.nousresearch.com/install.sh | bash`；`source ~/.bashrc`；`hermes doctor`
- **內容重點**：安裝腳本做了什麼（uv/Python/Node/依賴）、doctor 的每一行含義
- **驗收**：doctor 無 ✗；能解釋 2 個 ⚠ 的原因與修法

> 💡 **判讀原則：⚠ 不等於壞，✗ 才是**。⚠（黃色）＝「選用元件未裝/未設定」，屬預期狀態；✗（紅色）＝真的壞了。看到一堆 ⚠ 不用慌，先確認沒有 ✗。

**安裝故障排解速查**（最常見 3 雷，都真的有人在第一次安裝踩到）：
| 症狀 | 原因 | 修法 |
|---|---|---|
| 安裝卡在 curl 下載 | 網路不穩 | 重跑一次；必要時用代理或離線安裝 |
| `libnspr4.so` 找不到 | 系統缺瀏覽器相依套件 | `sudo apt install libnspr4`；不裝也不影響 CLI 主功能 |
| doctor 出現 ⚠（非 ✗） | 大多是選用元件未裝 | 大多可 `hermes doctor --fix` 自動修；解釋不出的 ⚠ 先記下，H2 驗收只要無 ✗ 即可 |

> 💬 **還是卡住？** 把 `hermes doctor` 完整輸出貼到本書的**讀者服務中心**（見書末「讀者服務」一節）——安裝是最多人卡關的地方，你踩的坑很可能已經有人解過。

## 第 2 章 第一次對話（第 3-4 小時）

### 第 3 小時 ｜ 設定 Provider 並開始對話
- **動手做**：🖥️ `hermes setup --portal`（一次 OAuth 搞定模型+搜尋+圖片+TTS+瀏覽器）；`hermes` 問「你是誰」
- **內容重點**：Nous Portal、provider 與模型的關係
- **驗收**：完成一次真實對話，知道 portal 提供哪些能力

> 💰 **成本提醒**：H3 用的免費模型（如 `upstage/solar-pro4:free`）足以完成全書練習。付費模型、外部 API（H9/H11）有費用——每次切付費模型或在 H8 做比較實驗前，先確認 Portal 的計價頁，避免 100 小時悄悄燒掉一筆帳單。

> 🛂 **裝置授權流程（瀏覽器沒自動彈開時照這做）**：
> 1. `hermes setup --portal` 後，終端會顯示一串 **URL ＋ 裝置碼**
> 2. 瀏覽器沒自動開？**手動把 URL 複製到瀏覽器**打開，輸入裝置碼（WSL 缺 `libnspr4` 等相依時瀏覽器不會自動彈出，但手動開完全不影響）
> 3. ⏱️ 裝置碼有時效（約 5-10 分鐘）——過期就重跑一次流程，不用怕

### 第 4 小時 ｜ 三種對話模式
- **動手做**：🖥️ 互動模式 / `hermes -z "..."` 單行 / `hermes --resume` 續接；試 3 個斜線指令
- **內容重點**：什麼時候用哪種模式、session 的由來
- **驗收**：隨機抽考能正確選用模式

## 第 3 章 命令列操作（第 5-6 小時）

### 第 5 小時 ｜ CLI 子指令巡禮
- **動手做**：🖥️ 逐一跑 `hermes model / tools / config get / sessions / status`，記錄輸出
- **內容重點**：常用子指令地圖、`--help` 的用法
- **驗收**：不看文件列得出 8 個子指令的用途

> ⚠️ **互動式 vs 純輸出**：`hermes model`、`hermes tools`、`hermes setup` 這類會開「互動選單」的子指令（**連 `hermes tools --summary` 也是**），**需要真實終端**——直接 pipe 到 grep/檔案會卡住或報錯。自動化情境請改用 `-z` 單行模式或配合 `script -qec`（pty 包裝）。遇到「執行後沒輸出」先確認是不是互動式指令。

### 第 6 小時 ｜ TUI 介面
- **動手做**：🖥️ 練習輸入/歷史捲動/快捷鍵，完成一次純 TUI 工作流
- **內容重點**：TUI 佈局、與 CLI 的關係
- **驗收**：能順暢完成一次 TUI 對話工作流

## 第 4 章 設定與工具（第 7-10 小時）

### 第 7 小時 ｜ config.yaml 解析
- **動手做**：📖 Configuration 文件；🖥️ 開 `~/.hermes/config.yaml` 標出三大區塊
- **內容重點**：config 檔與 `.env` 的分工
- **驗收**：能指出任一選項在檔案哪一節

### 第 8 小時 ｜ 模型切換實驗
- **動手做**：🖥️ `hermes model` 切換第二個模型；🧪 比較同一問題的回答
- **內容重點**：模型選擇的取捨（成本/速度/品質）
- **驗收**：用一句話描述兩模型差異 + 何時該用誰

> 🏷️ 模型名格式＝`provider/模型:變體`（例：`upstage/solar-pro4:free`）。看到名字就懂它是哪家、哪個模型、什麼變體——這是理解所有模型相關設定的鑰匙。

### 第 9 小時 ｜ 工具與授權機制
- **動手做**：📖 Tools & Toolsets；🖥️ 巡邏 10 個常用工具，測試授權流程
- **內容重點**：60+ 工具分類、需授權的行為、如何開關工具
- **驗收**：能預測哪些操作會要求授權

### 第 10 小時 ｜ 程式碼執行
- **動手做**：🖥️ 給 Hermes 一份 CSV，叫它用 `execute_code` 分析並回報
- **內容重點**：`execute_code` 的威力與邊界
- **驗收**：拿到正確分析結果，能解釋執行環境

> 🛡️ **防「幻想」驗證技巧**：要確認 agent 真的執行了程式（而非嘴上說說），叫它**寫一個檔、再讀回來印出來**——磁碟上的檔案不會說謊（例：`寫檔案 /tmp/test.txt 內容 abc，再用 Python 讀回印出`）。這是全書最值得帶走的實測技巧。

> **🏁 第 1 部驗收**：用 Hermes 完成一個日常任務（讀檔→分析→產出），並能向旁人解釋過程。✅ **過關後**：到本書讀者服務中心的「成就展示」分享你的第一個任務吧（書末「讀者服務」一節有網址）。

- **內容重點**：context file 的運作原理
- **驗收**：它能正確回答該文件內容的問題

### 第 13 小時 ｜ 有無 Context 對比
- **動手做**：🧪 同一問題「有餵/沒餵」各答一次，記錄差異（提示：🖥️ `hermes prompt-size` 可離線量化 system prompt / 工具 schema / 記憶各佔多少位元組——工具 schema 常是 system prompt 的 3 倍）
- **內容重點**：context 對回答品質的影響幅度

### 第 14 小時 ｜ Context 策略設計

- **驗收**：有一份實際可用的策略文件

> ℹ️ 想「平行跑兩個獨立任務」？用 `-z` 開兩個背景＋`wait` 最快（實測 23 秒完成雙任務）。`--worktree`（`-w`）是給「多 agent 改同一 git repo」的隔離模式——**只在 git repo 內有效**，在一般目錄不會報錯、只會正常回應，別誤以為已隔離。

## 第 6 章 記憶系統（第 15-19 小時）

### 第 15 小時 ｜ 記憶原理
- **動手做**：📖 Memory 文件；🖥️ 查看記憶存放位置與格式

## 第 8 章 自動化 Cron（第 26-30 小時）

### 第 26 小時 ｜ Cron 原理
- **動手做**：📖 Cron 文件；拆解 5 個 expression 的含義
- **內容重點**：排程語法、投遞目標
- **驗收**：能解釋與撰寫基本 expression

> ⚠️ **最重要的一句話：排程 ≠ 自動執行。** cron job 排好了，**必須有常駐的 gateway 服務才會自己觸發**（`hermes gateway install` 見第 9 章）。本教程改為：先學會「建 job + 用 `hermes cron run <id>` 手動觸發」驗證邏輯正確；要不要真的讓它全天候自動跑，等 H33 學會 gateway 再決定。別傻等 job 自己 fire——它不會。

### 第 27 小時 ｜ 第一個 Cron 任務
- **動手做**：🖥️ 建立定時輸出任務到 CLI，確認準時執行
- **內容重點**：cron 指令、任務型態
- **驗收**：任務準時執行

> 💡 **cron 雙雷**：① 同名任務！cron 允許重複名稱，刪除/暫停**一律用 job ID** 而非名稱；② `--paused` 可先建後啟（避免一建成就觸發）。查詢用 `hermes cron list`，測試單次執行用 `hermes cron run <id>`。

### 第 28 小時 ｜ 每日摘要專案
- **動手做**：🖥️ 建「追蹤 2 個網站 → 定時摘要」任務
- **內容重點**：把多工具串進排程
- **驗收**：摘要如期產出

### 第 29 小時 ｜ 除錯演練
- **動手做**：🖥️ 故意設錯 expression，用 doctor/logs 修復
- **內容重點**：cron 常見失敗模式與排查
- **驗收**：能自己定位並修復

### 第 30 小時 ｜ Script-only 模式
- **動手做**：📖 cron-script-only；🖥️ 跑一個純腳本任務
- **內容重點**：不需要 agent 的輕量排程

### 選擇題（6 題）

1. 下列哪個 `hermes` 子指令**需要**在真實終端操作（無法直接 pipe）？
   A. `hermes sessions list`　B. `hermes model`　C. `hermes config get`　D. `hermes cron list`
   → B。互動式選單類指令需要真實終端（可直接用 `-z` 或 pty 包裝繞過）。

2. 授權模型的「allowlist（白名單）」精神是？
   A. 預設允許一切　B. 只允許白名單內的操作　C. 每次全手動確認　D. 不做任何授權
   → B。白名單以「預設拒絕、列名才放行」為核心。

3. Skills（技能）在 Hermes 中的定位最接近下列何者？
   A. 對話風格設定　B. 程序性記憶（step-by-step 的標準做法）　C. 編譯器外掛　D. 排程規則
   → B。技能是「給 agent 的重複性做法」，由本體提示＋檔案構成。

4. 要暫停或刪除 cron 任務，最安全的方式是？
   A. 用任務名稱操作　B. 用 job ID 操作　C. 重開機　D. 刪除設定檔
   → B。cron 允許同名任務，名稱不唯一；job ID 才是唯一識別。

5. MCP 的全名與意義是？
   A. Model Context Protocol（模型-工具間標準協定）　B. Multi-Chat Platform　C. Meta Control Panel　D. Mobile Command Protocol
   → A。MCP 讓 agent 以統一協定接上外部工具/資料源。

6. 想快速確認 Hermes 安裝與環境健康，應執行？
   A. `hermes status`　B. `hermes doctor`　C. `hermes check`　D. `hermes health`
   → B。`hermes doctor` 逐項檢查相依與環境；多數 ⚠ 可 `--fix`。

### 簡答題（4 題，每題 2.5 分）

7. 說明「互動模式」與「`-z` 單行模式」的差異，各適合哪種情境？
   評分基準：互動模式＝真實終端、多輪選單、適合探索／`-z`＝單行非互動、適合自動化與管道。各 1 分＋舉例 0.5 分。

8. 寫出你實作過的 3 種「把 Hermes 特化給自己」的方式，並說明各自的**儲存位置**。
   評分基準：任舉 3 種（技能/plugin/cron/自訂工具/MCP）→ 各 0.5 分；說對儲存位置（如 `~/.hermes/skills/`、`plugins`、`hermes cron list` 可見）→ 各 0.3 分。

9. 敘述一次完整對話中，context（上下文）從哪裡來、最後流向哪裡。
   評分基準：能提到 session 紀錄、內建記憶（fact/preference）與 prompt 組裝三者任一環節，且描述完整無誤 → 滿分；說出「記憶在下次 session 仍可用」→ 加分。

10. 若要為自己的使用情境選部署方案，你會考慮哪些維度？
    評分基準：提到成本、隱私、離線需求、可用性/延遲、維護成本中任 3 個維度且說明取捨 → 滿分。
