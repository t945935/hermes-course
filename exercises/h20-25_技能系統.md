## H21 技能結構（inspect pdf 實測）
技能 = 一個目錄，核心是 **SKILL.md**：
```
skills/productivity/pdf/
├── SKILL.md              ← YAML frontmatter + 使用指引（何時用/怎麼用）
├── references/           ← 深水區知識（OCR、nano-pdf 編輯）
├── scripts/              ← 可執行工具腳本（pdf_read.py, pdf_split.py…）
└── (assets, templates…)
```
SKILL.md frontmatter 範例：
```yaml
name: pdf
description: "PDF files: create, read, merge, fill, OCR, edit text."
version: 1.1.0
author: Nous Research
metadata.hermes: {tags, category, related_skills: [docx, xlsx, powerpoint]}
```
→ **技能不是程式，是「何時用什麼工具/腳本/知識」的專業操作手冊**

## H22 技能 vs 工具（關鍵差異）
| | 工具 (Tool) | 技能 (Skill) |
|---|---|---|
| 本質 | 可呼叫的函式（API schema） | 知識包（SKILL.md 指引） |
| 注入成本 | 全 schema 39KB 注入 | 只有 index 5.2KB，用到才載全文 |
| 例子 | web_search, execute_code | pdf（讀寫合併 OCR 全套流程） |
| 關係 | 技能會**指揮**工具 | 工具被技能使用 |

## H23-H24 技能生態系（skills.sh / github / clawhub）
- `hermes skills browse` 瀏覽、`search` 搜尋、`install` 安裝
- 同名技能很多版本：光 `pdf` 就 20 個（official anthropics/openai + community）
- 安裝要用完整識別碼：`skills-sh/anthropics/skills/pdf`
- 管理：trust/untrust（專案技能信任）、check/update/audit、opt-out/opt-in、list-modified/diff（自改內建技能追蹤）
- 發布：`publish`、`snapshot`、`tap`（自訂源）

## H25 技能載入策略（實戰心得）
- 預設 53 技能 index 就自動載入（5.2KB 成本很低）
- `hermes --skills <name>` 可指定載入
- 同名衝突時用 sources 區分：builtin / skills.sh / github / clawhub / local
- 專案技能（repo 內 .hermes/skills）需 `hermes skills trust <dir>` 才載入
